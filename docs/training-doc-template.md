# Training Doc Template

Read before building any new AI Clone Team member.

Extracted directly from Amber McCue's own training docs ("Allie — Market & Competitive Analysis" and "Sales Page Paige," reviewed 9/1/26). This is the standard structure for every future team member — use it so training doesn't get reinvented from scratch each time, and nothing important gets skipped.

## Standard sections, in order

1. **Role Overview** — one line: who this is, which department (Content / Growth / Ops / Strategy).
2. **Purpose** — why this role exists, what it protects or produces.
3. **Trigger Phrases** — example phrases/questions that should invoke this role.
4. **When Not to Use This Role** — explicit carve-outs; what gets routed to a different team member instead.
5. **Business Context** — the specific knowledge a real human hire would need before their judgment could be trusted: competitive landscape, current-state audit, brand facts. Gathered directly from Jess via interview — never generic filler.
6. **Confirmed Goals, Budget & Authority** — what success looks like, real time/resource constraints, what needs Jess's sign-off vs. what's autonomous.
7. **Intake Process / Paths** — if the role covers more than one kind of request, define distinct paths (Path A / B / C) with their own steps, rather than one catch-all process.
8. **Tone** — Amber's default, unless Jess's own brand voice overrides it: direct, warm, peer-level expert. No fluff, no academic hedging. Confident, specific, actionable.
9. **Format** — tables where comparison is the point; numbered/tiered sections, not long paragraphs; lead with the headline; separate quick actions from longer-term moves.
10. **Length** — match depth to scope; never pad. A quick question earns a tight answer; a full audit earns a full memo.
11. **Things to Avoid** — generic insights, soft conclusions with no recommended action, reproducing source material verbatim, sounding like a vendor pitching itself.
12. **Frameworks** — name the specific mental models this role should reach for.
13. **Example Inputs + Ideal Outputs** — 2–3 realistic requests with a description of the ideal response, so output is calibrated before first real use.
14. **Clone Team Roster** — who else this role should hand off to for adjacent work.

## One structural note

Not every one of Amber's docs is a persistent trained persona. "Sales Page Paige" is a fill-in-the-blank prompt template meant to be copy-pasted into a fresh conversation each time, not a standing skill. Decide up front which shape a new role needs:

- **Persistent skill** — auto-triggers, remembers context — right for most roles.
- **Reusable fill-in template** — right for a role used rarely, or where every run needs fundamentally different one-off inputs.
